### 目标

把 dsh-awf-dashboard 的 `copy-workflow-assets.mjs` 技能源从「本机已安装实体 ~/.dsh/skills/agent-workflow-scaffold」收敛为「仓库（或发布 tag）」，使 npm 包内嵌技能 = 发布版本的技能、可复现可校验：

1. 打包内容与发布版本强绑定：manifest 不再写死本机源路径（当前 skillSource 是 /Users/chenlin/...）。
2. 发版前无需先 install.sh 同步本机实体（现状：实体旧则包内技能旧；--skill-dir 指向仓库根会误内嵌 .agent-teams/**）。
3. 其他用户 `dsh plugin add` 拿到的技能与 CLI 同一版本来源，--check 对发布包有效。

### 背景（DEV-216 memory/history 已记）

- 插件 1.6.0 已内嵌 24 项技能文件（npm pack 验证），但内容 = 实体 1.6.0（DEV-216 前规则），CLI = 仓库最新——源不同步的产物。
- copy 脚本源设计：技能 ← 实体；bin/awf ← 仓库。需统一为「仓库为唯一源（或发布 tag 快照）」。

### 验收标准

- [ ] copy 脚本技能源改为仓库（或 --skill-dir 显式指向仓库内技能目录），manifest.skillSource 记录发布版本标识（tag/commit）而非本机绝对路径
- [ ] 仓库根 .agent-teams/** 不会被当成应内嵌文件（--check 不报 DRIFT）
- [ ] 打包产物 = 当前发布技能的快照：--copy → --check 一致；npm pack 含最新规则（收工三步/Execution Log）
- [ ] 发版流程文档注明：发版 = 切 tag → copy → pack，不再依赖本机实体状态
