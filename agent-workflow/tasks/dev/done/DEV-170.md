### 背景与问题
- `--report` 经 `session/prompt` 投递回报＝用户消息；DSH GUI 只渲染 assistant 消息（含 dsh-ui 围栏），用户消息永远纯文本——已实测确认（围栏不渲染）
- 用户诉求：回报**本体**以结构化卡片呈现（不是派发方转达副本）；AgentTeams 能渲染因它是 DSH client 插件（chat.node 槽位织 React 卡片）

### 目标
扩展 dsh-plugin：回报消息（【回报投递】或附机器标记）在会话消息流中渲染成结构化卡片（时间/来源/派发方/派发单/正文），普通消息不受影响，agent 侧读取不受影响（节点数据不变）。

### 方案（v2：架构调整——数据与渲染分离，AgentTeams 式）
> chat.node 直投文本方案实测失败（组件被调用但宿主不渲染用户消息节点的 chat.node 内容；AgentTeams 从不注入文本）→ 用户拍板改架构。

1. **回报落盘**：`--report` 双写——结构化 JSON（`<项目>/dispatch/reports/<票据>-<ts>.json`：ticket/time/source/dispatcher/status/body/reportedAt）+ 文本投递（唤醒派发方）；纯函数 `write_report_json` / `report_status_of`（DISPATCH-153 状态解析）
2. **聚合路由**：dsh-plugin 服务端 `GET /awf/reports`——读所有登记项目 `dispatch/reports/*.json` 聚合（reportedAt 倒序）
3. **回报面板**：dsh-plugin 客户端边栏页签「回报」（sidebar.right.pane.tab + better-sidebar 双通道）——列表（时间/来源/票据/状态徽章）+ 点击展开正文；15s 轮询
4. 回退：无插件环境回报仍为纯文本（现状不变）；旧回报文本格式仍可读

### 修订 v2（最终形态——用户确认）
- 会话头部入口（header.actions）实测渲染成功，但用户弃用（「我不需要头部的入口」）→ **已移除注册**（通道 1e 删除，2026-11-05）
- 最终形态：**边栏「回报数据」页签（betterSidebar awf-reports，/awf/reports 聚合）+ JSON 数据层**；会话头部只保留 agent-teams 原生元素
- Web 实机验证：+ 菜单添加「回报数据」页签成功 → 面板渲染（DEV-170 面板上线 | 完成 | 15:43:48 | 来源→派发方）→ 点击行展开正文；数据层 2 条回报 15s 轮询
### 结论（v3：AgentTeams 观察后定型——聊天框内卡片宿主不支持）
- 浏览器独立验证（Electron + GUI cookie）：chat.node 组件被调用但宿主不渲染 user/message 折叠节点输出；turnTail 槽位本环境不渲染；session/append 注入 404 不存在——**宿主当前无「插件把消息渲染成聊天框内卡片」的通道**
- AgentTeams 实测观察：成员回报 = send_message → captain inbox 的结构化文本，**同样不渲染消息流卡片**；其聊天框呈现 = 会话头部入口（header.actions）+ 进行中工具折叠卡片（tool 事件，短暂）+ 边栏团队协作页签
- 定型：**会话头部 📮 回报入口（header.actions，与 agent-teams 同槽位同框）+ 边栏「回报数据」页签（betterSidebar 注册，/awf/reports 聚合）+ JSON 数据层**——与 agent-teams 的「头部 + 边栏」模式对齐
- 诊断遗留：window.__reportCardData / __reportTurnCard 调试标记（无害，后续可清理）
