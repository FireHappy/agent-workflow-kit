### 背景

派发复用池按「同 cwd + [awf] 前缀 + 空闲 + 最新 updatedAt」选池，忽略任务/派发者域与上下文污染。用户要求改为「每次 `--new` 新建 → 任务完成核验后物理删除该会话」。派发方初查只看到 `workspace/archiveSession`，随后在 asar 中发现 `session/delete` 字样并要求补证；另报 `--session` 硬指定时被池监听改选的串台 bug。

### 宿主能力结论（补证后定稿）：**DSH 0.2.2-rc.1 没有可用的会话物理删除能力**

asar 逐文件扫描（20529 文件）后，`session/delete` / `deleteSession` / `zDeleteSessionRequest` 只属于：

- `@agentclientprotocol/sdk`（第三方 **ACP** 协议 SDK：schema / zod / AGENT_METHODS / client `deleteSession()` / 协议测试）
- `dsh-session-query-sqlite` 的 **FTS 搜索索引** `_deleteSession`
- `dsh-experimental-inspector` 的 Chrome DevTools device-bound session（无关）

**A. 语义与调用路径**：`session/delete` 是 ACP **agent 侧**请求，ACP client → agent，参数 `{sessionId}`（`zDeleteSessionRequest`），返回空对象；仅当 agent `initialize` 声明 `sessionCapabilities.delete` 时可用。JSON-RPC（stdio/WS），**不是 MCP**，也不是 dashboard 的 `/api/*` RPC。

**B. 宿主是否实现**：**否**。`@deepseek-ai/dsh-acp` 的 `initialize` 只声明 `sessionCapabilities: {close, list, resume}`；连接只注册 `session.new/list/resume/close/setConfigOption/prompt/cancel`，**没有 `deleteSession` handler**；README 明写「listing, resuming, and closing…but **deletion**、forks、transcript replay…**unsupported**」。

**C. 排除理由（不止查 destroy/purge）**：

1. `session/delete` 字符串全部来自 ACP SDK；DSH 包没有调用 SDK client 的 `deleteSession()`。
2. DSH 作为 ACP agent 不实现 / 不声明 delete。
3. `_deleteSession`（sqlite）= 删 FTS 索引行（`persisted_docs` / `temp.live_docs`），不是会话数据、不暴露。
4. inspector 的 `deleteSession` = DevTools device-bound session，无关。
5. `it.each([... "session/delete" ...])` 是 SDK 协议测试（无 session header 时拒绝），不是 DSH 行为。
6. DSH Web 端点清单（`typert.host.js`）无 delete/destroy/purge；实测 `POST /api/session/delete`、`/api/session/destroy`、`/api/workspace/deleteSession` 均 **HTTP 404**；`workspace/archiveSession` 仅隐藏；`workspace/delete` 保留文件与会话；会话右键菜单无删除；会话后端文档自述「不删除会话文件」。

### 最接近替代（已落地）

`--retire-session <会话ID> [--apply]`（仅 `[awf]` 派发会话）：归档 + 写本地归档台账 `.dispatch/archived-sessions.json`，会话退出复用池 / GUI 分组。差异（如实上报）：**不回收磁盘、可经 `workspace/unarchiveSession` 恢复、`~/.dsh/sessions/` 仍保留**；**不硬删任何文件**。流程：`--new` 派发 → 必报点 10 回执 → 派发方核验 → `--retire-session <ID> --apply` → `--prune` 删票据。

### 附带修复：`--session` 硬指定禁止改选

- `wait_session_ready(..., allow_reselect=False)`：`--session` 路径只等指定会话，不启动整池监听、绝不改选；
- `dispatch_session` 调用处加防御：返回会话 ≠ 指定会话即中止发送（避免误投）；
- 复用 / 自动选池路径保持 DEV-224 整池监听语义不变。

### 附加（用户追问）：权限牌一致性

DSH 在创建会话时读取 profile 的 `permission.defaultPreset`，GUI 新建与 `--new` 新建默认继承同一预设；当前实测 `defaultPreset = danger-full-access`、当前会话权限 = danger-full-access。新增只读自检 `--permission-state`；会话创建接口无权限参数，无法按单次派发单独授权。
