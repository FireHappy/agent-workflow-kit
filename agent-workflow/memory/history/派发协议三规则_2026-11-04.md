# 派发协议三规则（DEV-132/DEV-138）沉淀

日期：2026-11-04 ｜ 结论来源：用户决策（两个执行偏差）→ 协议修正

## 背景：两个执行偏差

1. **router 前置分析过多**：router 替目标 worker 侦察 build_guide / 历史产物 / 场景清单等——本应归目标 worker 自己的会话（它有目标仓库 tools/ 手册与 memory/history），有问题再返回 router / 用户决策。
2. **主会话 --wait 钉住**：派发时主会话用 `--wait` 阻塞等回合；派发动作本质就是启动子代理，无需 `--wait` 钉住 router，也无需为「并行/汇总」启动智能体团队。

## 三条规则（落盘到 docs/dispatch.md、templates/AGENTS.md.tmpl、cross-project 工作流、design.md、team-flow.md、派发技能）

1. **默认异步**：`awf-dispatch` 只发送并返回会话 ID，主会话不被钉住；`--wait` 是显式开关（需要回合结果/落地确认才加，配 `--timeout`）。
2. **派发即启动子代理**：派发动作=在目标工作区启动目标 agent 的子代理会话；**不启用智能体团队承载派发**（无 captain/dispatcher 成员层）。多目标=多次派发（异步互不阻塞）；`--team` 仅作显式 opt-in 的目标侧拆队建议。
3. **票据瘦身 + 分析归 worker**：router 只写 用户意图 / 硬约束 / 验收标准 / 路由裁决，不写执行步骤、不做前置侦察；前置分析由目标 worker 用 target 的 tools/ 手册 + memory/history 完成，有疑问返回决策。

## 关键改动点（kit 双副本机制）

- 模板有两份：`templates/AGENTS.md.tmpl`（源）与 `agent-workflow/templates/AGENTS.md.tmpl`（框架副本，**awf bootstrap 实际渲染这份**）；`check_workflow.sh` 的 copy_drift_report 做双向比对——**改模板必须同步两份**，否则 check FAIL。
- 跨项目工作流同样双份：`templates/workflows/cross-project.md` 与 `agent-workflow/workflows/cross-project.md`，必须一致。
- 派发技能 `skills/cross-project-dispatch/SKILL.md` 是随 install.sh 分发的操作文档，改派发规则必须同步（它曾写「默认：派发即建队（团队模式）」）。
- 根 AGENTS.md：「受控区块」由 bootstrap 生成（digest 会变，如 75691332 → 7354b7d6）；「协作约定」在区块外，需手工维护。
