# 升级批次教训：v1.1.3 全项目升级（2026-11-05）

> 主题：全项目升级批次（DISPATCH-144 → kit DEV-151/152）。同类：`版本锚点可配置_version_file_2026-11-04.md`（DEV-145）、`门禁严格度优化_2026-11-04.md`（DEV-148）。

## 结论

1. **G3 门禁拦截 ≠ 必须等待**：目标项目有 active 任务或脏工作树时，先读该 active 任务的「修改范围」/脏改动清单，与本次升级的 `agent-workflow/` 写入范围不重叠即可 `--allow-active` / `--allow-dirty` 豁免（三选项之一），不必死等。本次 5/9 项目走豁免：dsh-settings（DEV-013 verify 改 scripts/）、openxr-uxr（DEBUG-001 verify 改 runtime 日志）、uxrsample（DEV-077 kit 派发锚点）、naboo/rokid（Unity 工程遗留脏改动）。豁免理由须写进派发账本。
2. **bash heredoc 传中文参数有坑**：UTF-8 locale 下 `cat > file <<EOF` 内嵌 `$var` 紧跟全角字符（如 `$id（`）会产出乱码（`file` 报 Non-ISO extended-ASCII）。规避：用已正确生成的 UTF-8 文件为底版，`sed` 按字节替换生成其余；或直接 write 工具写死。
3. **uxrsample 锚点按 version_file 落盘**：`version_file: agent-workflow/VERSION` → 升级后锚点写 `agent-workflow/VERSION`，根 `VERSION` 保持不存在（避免 macOS 大小写不敏感 FS 上根 VERSION 撞 C++ `<version>` 头，见 DEV-145 memory）。核验时按 `project.yaml` 的 `version_file` 读，不要默认根 VERSION。
4. **FinderPathBar 无 plist 回归**：DEV-007 后锚点写根 `VERSION`（不再碰 Info.plist），本次升级 commit `fdd5f3b` 文件清单 9 项均工作流相关，无 Info.plist 变更——DEV-007 的 plist 陷阱已持续规避。
5. **升级批次收尾铁律（本次踩坑）**：账本登记（收讫表等）后**必须**跑 `awf status` 刷新 `status.md` 再提交，否则 `check_workflow.sh` 因「status.md 已过期」红灯（review 硬性不通过项）。正确顺序：改账本 → `awf status` → `check_workflow.sh` → scoped commit。
6. **CHANGELOG Fixed 条目措辞**：历史段按发版规则不改写；若要标注历史遗留问题，写「标注：…（历史遗留，按规则历史段不改写，此处仅作标注说明）」，不要写「更正/去重」造成与实际不符。
