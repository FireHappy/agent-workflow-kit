# 空闲/收尾/自检报平安：无任务发生也报平安（DISPATCH-147，DEV-157）

日期：2026-11-05。目标：消除「又来了又没给你回报」观感——核查确立：非任务未回报，而是「无事发生」时缺报平安（任务完成回报后会话默默安静，派发方/用户无法区分「正常空闲」与「卡住失联」；自检/自测动作也不产生回报）。

## 三类新回报点（复用 DEV-156 --report 通道，不新造；命令接口零变更）

1. **收尾报平安**：必报点 10 完成回报后追加收尾句「任务完成，会话空闲，可续发（来源会话：<会话ID>）」，随完成回报一并投递；不再默默安静结束。
2. **空闲心跳（防「卡住」误判）**：完成收尾后 / 等待外部已报阻塞后，会话仍存活且距上次回报 >10 分钟无新必报点回报时，主动回报「空闲心跳：空闲+仍在线+上次动作时间+无卡死声明」；此后每 ≥10 分钟一次，或仅在有活动变化时立即合并更新。
3. **自检/自测透明**：非任务动作（bootstrap 校验、通道自检、仓库体检等）可选发「自检状态」回报（做了 X / 结果 OK），走同一 --report；不强制、不打断任务主线，多动作可合并一条。

## 防刷屏（合并策略，定死）

- 空闲心跳与**已报过的最后状态合并**：无新进展不重复整段回报，只声明「仍空闲在线」。
- 与执行中的 **5-10 分钟中途状态错峰不叠加**（执行中走中途状态，空闲走 ≥10 分钟心跳）。
- **阻塞心跳优先**：等待外部（阻塞态）按转派链「仍阻塞」心跳 ≤5 分钟优先，空闲心跳仅在其缺席时兜底——两套心跳互斥不撞车。
- **自检不计入也不替代空闲心跳**（自检是范围外可选透明，缺席不触发违约；空闲心跳是必定义务）。

## 与静默=违规（DISPATCH-155）衔接

正常空闲与静默等待/失联的区别 = **空闲心跳是否发出**——「空闲也要报」是既有「静默等待 = 违规」的反向义务；无心跳且无回报 → 派发方按既有「疑似失联」流程处理不变（追问 → 登记滞留 → 上报用户重派/干预）。
