# 看板流程渲染：阶段信息必须行内联 + 紧凑阶段徽章参考 AgentTeams（DEV-179）

日期：2026-11-06 ｜ 结论来源：DEV-179（看板插件 0.3.5，用户反馈「当前任务要点击详情才看到流程阶段」「流程画得太难看，参考 agent-team 布局」）｜ 看板 UI / 流程渲染类 review 必读

## 结论（铁律）

1. **用户可见的关键状态必须行内联，不能埋在详情里**：用户抱怨「当前任务要点击进度详情才能看当前到哪个流程了」——阶段信息只在点击行打开源文件后才可见 = UX 缺陷。看板行的信息层级：一瞥即知的信息（当前流程阶段、状态、优先级）必须直接渲染在行内；详情/编辑才需要点击。
2. **大步骤条（横向节点轨道 + 呼吸圆点 + 流动连线）用户观感差，不要再用**：曾经自诩「AgentTeams 视觉语言」的 `WorkflowSteps` 大步骤条（16px 圆节点 + 连接线 + 呼吸/流动动画）被用户明确否掉。参考 AgentTeams 面板的实际做法是**紧凑行 + 状态色徽章 + 当前阶段强调**：阶段徽章（`流程 · <当前阶段> · 位置/总步数`）+ 迷你分段进度（5-6 个 5px 竖条，完成=状态色浅底 / 当前=状态色实底+静态光圈 / 未到=灰），blocked 徽章标注「⏸ 暂停」。纯静态强调、无动画（或仅克制装饰），box-shadow 光圈不影响布局。
3. **新增组件必须接入渲染或删除，不留死代码**：`WorkflowSteps` 组件在 0.3.4 里全仓库未被调用（死代码），正是它没有被用户看到过、观感问题长期未被发现的原因之一。本次直接删除大步骤条、替换为行内 `StageInline`；纯函数（`WORKFLOW_STEPS` / `inferWorkflowStage` / `stageSummary`）保留并导出供单测。
4. **布局稳定性继续守 DEV-026 约束**：阶段行必须是**固定单行高度**（阶段徽章 + 分段固定尺寸、nowrap、无动画），不能随内容变化造成行高跳动；hover 位移/阴影全部禁止。行内新增信息统一用独立固定行，不塞进会 wrap 的 meta 行。
5. **行内新增渲染要有结构级单测**：除纯函数单测（inferWorkflowStage / stageSummary 各类型/状态映射）外，用 ModuleLoader 桩加载 client.js + 展开函数组件树，对 `renderLedgerBody` 断言：每个当前任务行有 `awf-stage-chip`（文本含「流程 · 验证 · 4/6」）、blocked 含「暂停」、分段数=步骤总数、`awf-row-clickable` 的 onClick 保留（点击详情回归不破坏）。
