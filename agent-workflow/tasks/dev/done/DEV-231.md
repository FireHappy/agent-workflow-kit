### 问题（为什么需要去重）

- 现有「握手」只保证**发送成功**（send ok），不保证真的启动（DEV-230 已补启动确认），也**不保证同一票据只派一次**。
- 派发方重复触发（用户重派 / 派发方重试）→ 目标项目多会话、任务重复执行、账本撞号（2026-11-09、11-10 均实证）。
- 同名保护只查标题**完全相等**且只在自动新建路径；`--force` 可绕过；无跨派发方共享的在途记录。

### 设计（幂等键 + 在途台账 + 握手中继）

1. **幂等键** = 票据 ID（`ticket_task_id`）+ 目标项目 realpath + 内容 `sha256(text)` 前 16 位。
2. **在途台账** `$DSH_HOME/.awf-dispatch/inflight.json`（跨派发方共享；registry 文件锁原子写；TTL 24h 过期自动清理）。
3. **派发前检查**（preflight 后、选会话前）：命中「同票据 + 同项目 + 同内容」→ 拒绝（exit 2）并给出原会话 ID/时间；`--force` 跳过；内容变化（hash 不同）放行（同票据更新续派）；`--session` 显式续跑不参与去重；`--no-dedupe` 关闭。
4. **派发成功后**写入在途记录（status=`sent`；启动确认后 `started`），供后续重复检测。
5. 清理：TTL 过期自动清；运维可 `--no-dedupe` 或删除 inflight 条目。
