# 门禁严格度优化（DEV-148，票据 DISPATCH-139）沉淀

日期：2026-11-04 ｜ 结论来源：7 卡点实证（仅 G3 active 必要）+ 落地复盘

## 背景

dsh-im 实测当天 7 个派发卡点里只有 1 个必要（G3 active 防多写者），6 个过度保守——根因是门禁把目标仓库当「必须瞬间干净」的静态物，而异步多会话世界里它随时处于「正在改账本、还没刷 status」的瞬态。

## 三条落地规则（进 bin/awf-dispatch + docs/dispatch.md + SKILL.md + cross-project 模板）

1. **P0 等待放宽**：会话繁忙队列默认最多等 `--queue-timeout` 180s（原 60s）；`wait_for_idle` / `wait_for_turn` 超时前必须回报**中途状态**（已等秒数 / 目标 HEAD 是否变化 / 会话产出），不静默超时——呼应「必有回报」主机制；返回值语义（None / (None,None)）不变。
2. **P1 allow 粒度**：`--allow-dirty=tasks` 只豁免账本自我生成物（`tasks/status.md`、`tasks/*/README.md`、`dispatch/log.md`），业务/代码脏仍拒；裸 `--allow-dirty` 向后兼容全豁免；G3 active 报错给三选项（等它完 / `--allow-active` / `--new`）。解析实现：argv 预归一化把 `--allow-dirty=<scope>` 拆成 flag+scope，非法/空 scope 走 `parser.error` exit 2（不能用 `nargs="?"`——会把后面位置参数吞掉）。
3. **P2 瞬态豁免**：G1 `check_workflow.sh` 的 FAIL 行全部为「status.md 已过期」时（账本在动、缺的只是摘要）降级 warn 放行 + 提示目标侧 `awf status` 刷新时机；混入任何真缺损 FAIL 仍拦截。判定边界：returncode≠0 但无 FAIL 行 → 照常 FAIL。

## 踩坑（下次复用）

- **%s 参数个数**：三元表达式里条件格式化串参数个数不匹配（"已变"%2 参 / "未变"%1 参共用 `% (a,b)`）→ 未变分支必 TypeError——独立 reviewer 用「import 真实模块 + 真实 git 仓库 + timeout=0 直击超时路径」复现，主路径崩溃替代了 (None,None) 返回。修复：按分支分别格式化；并为该路径补了行为级 smoke 回归断言（S3.5）。
- **同仓并行会话**：本任务执行期间另一会话在发版 v1.1.2 + 派发升级 9 项目：① 我预占的 DEV-145 号已被它用掉 → 立即改认 DEV-148；② 工作树有它未提交的在途物（DEV-147.md、dispatch/log.md、dispatch/tasks/）→ 最终 commit 必须**路径限定 scoped add**，绝不 `git add -A` 扫走别人文件；status.md/README 是共享再生成物，谁跑 awf status 谁提交，内容收敛。
