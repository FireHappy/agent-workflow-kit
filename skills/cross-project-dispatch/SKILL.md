# agent-workflow · 跨项目派发（技能）

**适用**：把任务交给另一个项目 / 跨仓库协作 / 目标仓库 ≠ 当前工作区 / 需要 `awf-dispatch` 派发与回执管理。

**原则**：默认异步派发、必有回执、核验落地再归档。

**路径约定**：文中 `tasks/`、`memory/`、`tools/`、`project.yaml` 均指目标项目 `agent-workflow/` 下的相对路径。

## 随技能提供的工具

本技能自带 `scripts/awf-dispatch`（Python 3 标准库），不依赖脚手架技能。下文 `awf-dispatch` 均指本技能目录下的脚本；已安装时可调用 `${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch`。不提供脚手架下的旧派发入口。

## 四道前置门（G1–G4，缺一不可）

| 门 | 检查内容 | 不满足时 |
|---|---|---|
| G1 工作流 | 目标有 `AGENTS.md`、`agent-workflow/project.yaml`、`check_workflow.sh` | 先 `awf init`（需用户确认）；绝不向无流程仓库派发。仅「status.md 已过期」这类瞬态问题可 warning 放行 |
| G2 工作区 | 目标路径已登记为当前 harness 工作区（GUI 工作区列表 / `workspace.json`） | 在 GUI「添加工作区」，或 `awf-dispatch --add-workspace`；否则走 handoff |
| G3 可写 | 目标无已跟踪改动、无其他 active 任务 | `--allow-dirty=tasks` 只豁免账本自我生成物（status / README / log）。active 冲突三选一：等它完 / `--allow-active` / `--new` |
| G4 通道 | 目标工作区能创建会话（GUI 在线、认证有效、模型可用） | 回退 `--headless`（需用户同意）或 `--handoff` |

只读任务可放宽 G3，但仍建议在目标会话里执行，留下可追问的记录。

## 派发三规则

### 规则一：默认异步派发

只做「复用或新建目标工作区会话 → 发送任务包 → 记日志」，立即返回会话 ID，主会话不被钉住。
需要本回合结果或落地确认时，调用方**显式加 `--wait`**（配 `--timeout`）。

### 规则二：派发即启动子代理

派发动作的实质就是在目标工作区**启动一个子代理会话**，由目标 agent 独立完成并回执。
**不启用智能体团队承载派发**——没有 captain / dispatcher 成员层。
多目标就多次 `awf-dispatch`（默认异步、互不阻塞），需要结果时各自 `--wait`，或回到会话查看。

### 规则三：票据瘦身 + 分析归 worker

router 只写：**用户意图 / 硬约束 / 验收标准 / 路由裁决**。
不写执行步骤、不做前置侦察——前置分析由目标 worker 在自己会话里用目标仓库 `tools/` 手册与 `memory/history` 完成，有疑问返回 router 或用户决策。

## 调度方最小操作序列

1. 预检（不建会话）：`awf-dispatch <目标> <票据> --dry-run`，确认 G1–G4
2. 写票据：`dispatch/tasks/<项目>-<ID>-<slug>.md`（只含四类信息，见「任务包」节）
3. 派发：`awf-dispatch <目标> <票据>` — 默认异步，立即返回会话 ID，主会话继续做其他事
4. 需要落地确认：加 `--wait --timeout 900`；不加则稍后回 GUI 会话查看目标 agent 的五项回执
5. 收尾：写 `dispatch/log.md` → 更新本仓库账本 → `--prune` 归档票据 → 本地 commit
6. 有依赖的目标：等上游回执「成功 + commit 已落地」后再派；失败/超时按 `--wait` 退出码决定重试、改派或降级
7. worker 报「阻塞：需用户确认 X」：由你转述用户 → 拿到决策 → `awf-dispatch <目标> <票据> --session <会话ID>` 续发。worker 不在目标会话内提问，决策送达前不擅自行事

## 脚本行为与会话复用

`awf-dispatch` 默认异步执行（`--wait` 是显式开关）：

1. 跑 G1–G4，打印前置检查结果
2. 读取目标项目 cwd 下全部 `[awf]` 会话（**归档台账记录的会话 id 除外**）：闲置优先复用并改名；无闲置且少于 3 个才新建；3 个全忙则启动独立监听子进程，任一空闲后复用发送，不创建第 4 个；无跨项目全局上限；同项目新建决策经文件锁串行化、锁后重读池再决策
3. 发送任务包后立即返回会话 ID；加 `--wait` 才轮询到回合结束并确认落地
4. 把 `sessionId`、标题、模块、会话来源（复用/新建）、状态、目标 HEAD 写入 `dispatch/log.md`
5. 打印会话信息；后续细节由用户在同一会话继续提

### 会话命名与模块

- 标题固定为 `[awf] [派发者] [任务名]`，复用时动态改名；模块仅用于票据分类展示
- 复用池 = 同一项目 cwd 下全部 `[awf]` 前缀会话，不区分派发者/模块/任务名；**归档台账（`dispatch/archived-sessions.json`）记录的会话 id 不进池**（已归档会话不参加复用与每项目数量统计）
- 每项目 `[awf]` 会话最多 3 个；达到 3 个且全忙时由独立监听子进程等待空闲，不拒绝、不新建第 4 个
- 模块来源：`--module <名称>` > 票据可选行 `- 模块：<名称>` > 默认 `通用`
- 旧格式会话（无 `[awf]` 标记，形如 `<项目> · <任务>`）默认不迁移，只有两种情况复用并改名：
  - 该会话消息里含派发任务包标记
  - 显式加 `--allow-legacy-reuse`
- 用户自建的普通会话既无标记也无放行，不会被复用 / 改名 / 注入任务
- 选中的会话正在运行 → 进入等待队列；项目池满 3 个时启动独立监听子进程监听整个 `[awf]` 池，任一空闲后自动复用并发送；`--queue-timeout`（默认 180s）超时才回执等待失败，不静默新建第 4 个
- 上下文压力 ≥ 0.9 只提示「可考虑 `--new`」
- 只有并行独立需求、上下文污染、排障或模块隔离时才加 `--new`；**项目池满 3 个且全忙时加 `--new` 需再显式 `--allow-over-3`**（确认后本次超限新建写入派发日志留痕），不再静默绕过上限
- **新建并发互斥**：同一项目的新建决策用文件锁 `dispatch/.lock-<project>` 串行化，拿到锁后重读池再决策——并发方刚建出的可复用会话直接改复用，不重复新建（锁文件与台账都是派发方本地产物，不入库）

## 命令行参数

| 参数 | 作用 |
|---|---|
| `--wait` | 等待回合结束并确认落地（目标 commit 或账本归档）；**显式开关**，默认不等待 |
| `--timeout N` | 回合等待 + 落地等待总秒数，仅 `--wait` 生效（默认 600） |
| `--no-wait` | 默认行为的兼容别名，与 `--wait` 互斥 |
| `--reuse` | 默认行为：按「项目 + 模块」复用已有常驻会话 |
| `--new` | 强制新建会话（隔离/调试），与 `--reuse` 互斥 |
| `--allow-over-3` | 配合 `--new`：目标项目 [awf] 池满 3 个且全忙时显式确认仍新建（本次超限新建写入派发日志留痕）；不加则拒发（退出码 2） |
| `--allow-legacy-reuse` | 放行旧格式空闲会话迁移复用并改名 |
| `--module <名称>` | 模块名（标题 `[awf] <项目> · <模块>`） |
| `--session <id>` | 直接向指定会话发送（续跑 / 人工指定），不新建 |
| `--queue-timeout N` | 会话繁忙时队列等待上限（默认 180s） |
| `--dry-run` | 只做前置检查，不创建会话 |
| `--headless` | 回退 headless（默认后台启动，`--wait` 才同步） |
| `--handoff` | 只生成交接单，不执行 |
| `--add-workspace` | 目标未登记工作区时自动登记 |
| `--team` | 任务包附加团队拆分建议，目标方自行决定是否拆队 |
| `--force` | 允许同名会话重复派发（重试/同名续派） |
| `--allow-dirty[=tasks]` | 放宽 G3（需明确知道风险）；`=tasks` 只豁免账本自我生成物，业务改动仍拒 |
| `--allow-active` | 目标已有 active 任务时仍派发（明确知道并行风险） |
| `--check-role` | 软校验目标 role 与任务关键词交集：匹配通过 / 不匹配警告 / 无 role 提示，均不硬拒 |
| `--allow-role-mismatch` | 配合 `--check-role`：静默 role 不匹配警告 |
| `--prune` | 清理已完成票据（用完即删；默认 dry-run 只打印计划） |
| `--cleanup` | 满池治理：列出每项目超 3 的空闲 `[awf]` 会话（默认 dry-run 只列表） |
| `--forget-archived` | 重置本地归档台账（删除 `dispatch/archived-sessions.json`；其中会话恢复进入复用池与数量统计） |
| `--apply` | 配合 `--prune`（删除票据）或 `--cleanup`（归档会话）：真正执行（默认只打印计划） |
| `--json` | 机器可读输出（含 `reused` 与 `sessionId`） |
| `--report` | 回执投递模式：把回执文本经通道投递到派发方会话收件箱（见「回执投递通道」） |
| `--to <id>` | 配合 `--report`：派发方会话 ID（投递目标；缺省降级写收件箱文件） |
| `--from <id>` | 配合 `--report`：来源会话 ID（默认取当前会话 env `DSH_SESSION_ID`） |
| `--text "<报告>"` | 配合 `--report`：回执文本（缺省取第一个位置参数或 stdin） |
| `--ticket <ID>` | 配合 `--report`：关联派发单/任务编号 |

手工等价操作：GUI 左侧切到目标工作区 → 打开（或新建）会话 → 粘贴任务包。效果相同，只是没有自动前置检查与日志。

## 任务包（票据）

文件：`dispatch/tasks/<项目>-<ID>-<slug>.md`，只含四类信息：

```markdown
# <ID> <一句话目标>

- 来源：用户 | 工作流
- 类型：dev | debug | docs
- 模块：<名称>
- 路由裁决：目标=<别名> / 通道=awf-dispatch / 理由=<role 匹配说明>

## 用户意图
任务：<ID> <一句话目标>

## 硬约束
- 目标项目与任务 ID
- 修改范围：<允许改什么>
- 明确不做：<不做什么>
- 提交要求：只允许本地 commit，禁止 push
- 分析归属：前置分析在本会话内用目标仓库 tools/ 手册与 memory/history 完成，有疑问返回决策

## 验收标准
- [ ] <逐条可勾选，含必须实际执行的验证命令>
- [ ] 回执格式：状态 / 变更文件 / 验证结果 / commit / 阻塞
```

要点：

- 票据不写执行步骤、不做前置侦察
- 任务包不要依赖调度方上下文——目标 agent 是独立会话
- 来源=工作流时允许按需继续转派

## 必报点总表（1–11）

任一触发，目标会话必须**主动回执派发方**。异步派发同样适用。

| # | 必报点 | 内容 |
|---|---|---|
| 1 | 受理任务 | 已受理 + 对任务的理解一句话 + 计划/预计 |
| 2 | 开始执行 | 首个实质动作前：开始实施 X，预计 Y |
| 3 | 里程碑完成 | 里程碑结果 + 下一步 |
| 4 | 状态转换 | active→review / review→active：转换原因 + 结果 + 下一步 |
| 5 | review 不通过 | 问题清单 + 修复计划 + 预计 |
| 6 | 修复开始 / 修复完成待复审 | 修复内容 / 待复审 |
| 7 | 复审通过 / 再次不通过 | 复审结果 + 结论 |
| 8 | 需用户确认 | 「阻塞：需用户确认 X（问题+选项+建议+解除条件）」——不得在目标会话内提问 |
| 9 | 阻塞 / 依赖缺失 / 范围不清 | 阻塞点 + 原因 + 解除条件，保持等待、不得静默 |
| 10 | 完成 | 状态 / 产物 / commit / 验证结果 / review 结论 |
| 11 | 空闲 / 收尾 | 收尾句 + 空闲心跳（见「心跳硬约束」） |

### 回执时机（定死）

- 任一必报点触发后**一回合内**必须回执，不许拖到下一步
- 执行中途长时间无里程碑：**每 5–10 分钟**回执一次中途状态（在做 X / 已完成 Y / 预计 Z / 未卡死声明）
- 等待外部时回执「阻塞等待中」+ 已等时长，不静默

### 心跳硬约束

| 场景 | 频率 |
|---|---|
| 阻塞 / 卡点等待 | ≤5 分钟 发「仍阻塞」心跳 |
| 执行中无里程碑 | 每 5–10 分钟 中途状态 |
| 空闲（无新必报点） | ≥10 分钟 发空闲心跳（空闲 + 仍在线 + 上次动作时间 + 无卡死声明） |

- 静默等待 = 违规：记入任务账本，派发方按「疑似失联」升级（追踪 → 回执 → 上报用户决定重派 / 处分记档）
- 空闲心跳与执行中 5–10 分钟状态错峰，不叠加；阻塞态「仍阻塞」心跳优先，空闲心跳仅兜底
- 空闲心跳可「仅在有活动变化时」发，与最后状态合并防刷屏
- 正常空闲 vs 静默失联的区别 = 空闲心跳是否发出——空闲也要报

### 回执字段（固定，一项不能少）

- 当前状态：哪个必报点 / 任务状态（active / review / blocked…）
- 执行内容：完成的工作、成功与否
- 下一步：将做什么
- 预计：时间 / 是否等待外部
- （如适用）commit / 验证结果 / review 结论

### 违约后果（定死）

- 不按必报点回执 / 超时无中途状态 → 派发方按「疑似失联」处理：追问（`awf-dispatch --session` 发「状态在哪里？按必报点回执」）→ 追问无果登记滞留 → 上报用户决定重派/干预
- 「完成才报、中途全沉默」视为违约，review 时连坐
- 派发方同样受约束：收到回执必须核验 + 转达用户（如适用）+ 归档，不许只轮询不读会话

### 转派链（A→B→C）

- 必报点表对链条上每一跳都适用（C 报 B、B 报 A、汇到源头）
- 转派 ≠ 失联：转派方收到下家回执后必须继续向上游回执（「已转派 C 处理，C 回执 X」）
- 转派后 A 仍对该任务负责（跟进 / 追问 / 兜底）
- 卡点必报：卡点 = 阻塞（依赖缺失 / 外部输入 / 范围不清 / 需确认 / 工具失效 / 冲突待决 / 进程等待）→ 立即按必报点表回执上游：卡点类型 + 原因 + 已尝试 + 解除条件 + 预计
- 需用户决策的卡点逐层上抛，最终统一经 IM 送达用户

## 回执投递通道

worker 的回执**经通道投递派发方，非仅写会话**：

```sh
awf-dispatch --report --to <派发方会话ID> "<回执文本>"
```

- 派发后 prompt 会带「派发方会话」（= 运行 awf-dispatch 时所在会话的 env `DSH_SESSION_ID`）与命令示例
- 回执推送进派发方会话收件箱（inbox）并触发处理，无需轮询
- RPC 不可达 / 未注入时降级写收件箱文件：`dispatch/reports/inbox/<来源会话ID>.md`
- 投递头（项目名 + 会话名）由 `--report` 渲染，不属于正文

## 回执正文排版规范

禁止整段长文本，必须用 Markdown 结构化。固定骨架（任何必报点通用）：

```markdown
## ✅ 完成任务（<编号> · <任务名>）

- **状态**：done（已归档）
- **执行内容**：改动清单核对 + 框架入库提交成功
- **改动范围**：
  - 框架：README / check_workflow.sh / bin×2 / templates×2
  - 入口：AGENTS.md、VERSION（锚点）
  - 账本：任务块归档
- **commit**：`<hash>`（未 push）
- **验证**：check_workflow.sh 0 FAIL（终态复跑）
- **遗留/风险**：<如有>

任务完成，会话空闲，可续发（来源会话：<会话ID>）
```

其他必报点同骨架，只换标题状态词与符号：⏳ 阻塞进行中 / ⏸ 中途状态 / 受理任务 / 开始执行任务。

## 派发方转达用户回执格式

收到回执并核验后，转达用户按固定格式（三态任选其一）：

| 状态 | 符号 |
|---|---|
| 完成 | ✅ |
| 失败 / 核验不过 | ❌ |
| 阻塞进行中 | ⏳ |

模板字段：

```markdown
## <状态符号> <任务名>（发送者：<回执请求头>）

- **执行内容**：
- **改动范围**：
- **验证**：（含「我独立重跑确认」）
- **问题 / 风险**：
- **我的处理**：已核验 + 已归档 done，无需你操作
```

## 远程办公状态（remote）

需用户确认前先判定本机熄屏状态：`awf-dispatch --screen-state`

- `off` / `locked` = 远程办公状态（remote）：用户不在电脑前，但经 IM 在线随时可决策，**不等于离线**
- 回执须注明「远程办公状态（remote），请派发端经 IM 主动、立即通知用户决策」,**不原地死等**
- 派发方收到该标记 → 立即、主动经 IM 通知用户决策，或置待决队列（账本登记防遗忘）；用户远程决策后转述续发

## 僵尸会话与落地判定

复用旧会话可能遇到「僵尸会话」：回合 16–21ms 即时结束，零 assistant 输出、零工具调用，脚本会一直等到 `--timeout`。两类可靠性判定：

### 无进展快失败（退出码 4）

回合耗时 <5s 且零输出、零工具调用 → 立即返回 4：

```
会话疑似僵尸（回合即时结束且零输出），请用 --new 重派或在 GUI 重开会话
```

`--json` 的 `zombie`、`turnSeconds`、`sessionId` 与日志状态都会标明。
**僵尸判定优先于落地**：不要在僵尸会话上继续空等，先 `--new`（或 GUI 重开）再验证。

### 等落地（回合结束 ≠ 完成）

正常回合结束后每 10s 检查目标仓库，以任务发送前一刻的初始 HEAD 为基线：

- `git rev-parse HEAD` 变化，且 `initial..HEAD` 区间内任一 commit 消息**含本任务 ID** → 落地
- 或账本 `agent-workflow/tasks/<type>/done.md` 出现任务 ID → 归档即落地
- 只有无关 commit → 不算落地

超时返回 3，状态「回合已结束但任务未落地」，不要当成功。

## 退出码与失败处理

| 退出码 | 含义 | 动作 |
|---|---|---|
| 0 | 成功（headless 下仍需按「等落地」验落地） | 核验五项回执 |
| 1 | 未预期异常 | 保留输出原样回执，不静默重试 |
| 2 | 前置门不过 / 派发失败 | 补门（init / add-workspace / 等写者），或改派、降级 handoff |
| 3 | 回合结束但任务未落地（超时） | 会话保留不杀；回 GUI 看进度，加大 `--timeout` 重派（`--force`）/ `--session` 续跑 / 改派 / 降级 |
| 4 | 疑似僵尸会话 | `--new` 重派或 GUI 重开，不要续跑同一会话 |
| 5 | headless 进程非零退出 = 执行失败（非超时） | 按 `dispatch/headless/*.log` 排查目标侧错误后重派 |

常见错误：

| 错误 | 处理 |
|---|---|
| `workspace-missing` | GUI 添加工作区，或 `--add-workspace`；不要用 `cwd` 绕过 |
| `workflow-missing` | 先 `awf init` / 补齐 `agent-workflow/` |
| `writer-held` / `session/conflict` | 目标会话被 GUI 占用或写者冲突；切走/等待后重试 |
| `auth-required` / `connection refused` | 重开 GUI URL；或 `--headless` |

## 回退方案

回退由调度方决定并执行，派发链路里不设 dispatcher 成员层。

| 情况 | 回退 | 代价 |
|---|---|---|
| GUI 未运行 / 认证失效 | `--headless`（需用户同意） | 后台启动并立即返回输出路径；会话不在 GUI 工作区，用户不能直接续聊 |
| 无法创建会话 | `--handoff` | 只生成交接单，需用户手工在目标会话执行 |
| 目标未登记工作区 | `--add-workspace` 或 GUI 添加 | 否则会话落在 Ungrouped |
| 目标无工作流 | 先 `awf init` 再派发 | 不要跳过 G1 |

## 写者与账本边界

| 角色 | 写什么 |
|---|---|
| 目标 agent | 目标项目的 `tasks/**`、`status.md`、代码、commit |
| 调度方 | 只写自己的 `dispatch/log.md`、任务文件、归档台账（`dispatch/archived-sessions.json`）、锁文件（`dispatch/.lock-<project>`） |

- 不要跨仓库改目标账本
- 账本与 commit 归主线（调度方）；目标项目账本由目标 agent 写，派发者不代写
- 一个任务只有一个 Owner；目标已有 active 任务时不要并行派发同一模块
- 派发生命周期：派发前在派发方账本登记「进行中开发任务」（active：目标 worker / 关联票据 / 派发时间 / 一句话目标 / 验收标准）作**兜底锚点**；回执核验通过后归档 done（补完成日期 / 结果概要 / commit 引用）

## 票据生命周期（用完即删）

- `dispatch/tasks/*.md` 是一次性票据：派发时写入、目标完成后**删除**，不留存根（避免 `dispatch/tasks/` 无限堆积）；主目录只留在途票据
- `dispatch/log.md` 是永久日志，不清理
- 判定 completed：目标仓库提交消息含任务 ID，或目标账本 `agent-workflow/tasks/*/done.md` 已含该 ID；解析不到项目/任务 ID、目标非 git 仓库则判 unknown 并跳过
- 删除时机：目标必报点 10（完成回执）**且派发方核验收讫**后，不等批量全部结束——完成一个删一个（与 `skills/upgrade/SKILL.md` 同一策略）
- 特殊情况：目标门禁不通过（G1-G4 拦截）→ 票据保留至用户决策（补 init / 清理工作区 / 豁免），决策后重派或删除

```sh
"${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch" --prune           # dry-run：只打印计划
"${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch" --prune --apply   # 确认后真正删除（用完即删，不留存根）
```

## 满池治理（DEV-214 四件套）

每项目 `[awf]` 会话上限 3 个，长时间派发后可能堆积超限空闲会话。四件套配合使用：

1. **归档台账**：`--cleanup --apply` 归档的会话写入 `dispatch/archived-sessions.json`（本地、不入库）；组装复用池 / 统计每项目 `[awf]` 会话数时**排除台账记录的会话 id**——已归档会话不再占池、不再触发等待，避免「归档后仍在池里被反复等/复用」
2. **`--new` 上限校验**：目标项目池满 3 个且全忙时，`--new` 需再显式 `--allow-over-3` 确认，本次超限新建写入派发日志留痕；不加则拒发（退出码 2）——`--new` 不再静默绕过每项目并发上限
3. **并发新建互斥**：同一项目新建决策用文件锁 `dispatch/.lock-<project>` 串行化；第二个调用方拿到锁后**重读池再决策**——并发方刚建出的可复用会话直接改复用，不重复新建第 N+1 个
4. **`--cleanup`**：列出每项目超 3 的空闲 `[awf]` 会话（保留最近更新 3 个，运行中的超限会话跳过）；`--apply` 逐个经 `workspace/archiveSession` 归档并写入台账

```sh
"${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch" --cleanup            # dry-run：只列出计划
"${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch" --cleanup --apply    # 确认后归档超限空闲会话并写台账
"${DSH_HOME:-$HOME/.dsh}/skills/cross-project-dispatch/scripts/awf-dispatch" --forget-archived    # 误归档/要恢复时重置台账
```

**DEV-215 补充**（满池实测暴露的两处修正）：
- **满池等待以返回会话为准**：`wait_session_ready` 在监听子进程返回任一空闲会话后，发送 / 改名 / 日志一律使用该返回会话（此前作用于局部变量，等待目标 ≠ 发送目标，监听白等）
- **并发记账提示**：同项目活跃 `[awf]` 会话 >1 时，任务包自动注入提示，要求目标按票据任务编号登记账本 / commit——避免多个并行 worker 自排相同 ID 造成账本互相覆盖（UXR-POOL 002/003 曾撞 DEV-091）

## 验收与收尾清单

1. `--wait` 回合结束后，检查目标 agent 回执是否含五项：状态 / 变更文件 / 验证结果 / commit / 阻塞
2. 在目标仓库独立核对（关键命令不只看目标 agent 自述）：`git log -1`、`git status`、`./agent-workflow/check_workflow.sh`
3. 记录：会话 ID、任务文件、状态、目标 HEAD、时间
4. 用户后续细节优先回到同一会话；只有新目标或新任务才重新派发

## 禁止事项

- 派发方替目标写执行步骤、做前置侦察
- worker 在目标会话直接向用户提问（禁止 ask_user_question 等弹窗）
- 「完成才报」、中途沉默
- 静默等待超过约定心跳
- 跨仓库改目标账本
- 自动 push、改写 git history
- 同模块向已有 active 任务的会话并行派发
- 未验证的判断写成结论（应标「待确认」）

## 状态机与状态取值

- 状态只写：`active` / `blocked` / `review` / `verify` / `handoff`
- 每步更新任务块「状态 / 最近更新 / 下一步」
- 验证命令必须实际执行（compile / test）；不可用时写 `验证阻塞：<原因>` 并置 blocked
- 归档后必须跑通过校验；`status.md` 由 `awf status` 刷新才算完成
