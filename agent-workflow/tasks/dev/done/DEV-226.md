### 实现

- 在宿主 `conversation.session.header.corner`（对话头部右上角）注入「工作流」图标按钮（账本线条图标，title=打开 Agent Workflow 工作流面板）。
- 点击逻辑：优先 `ctx.get('betterSidebar').openTab({ type: 'awf-dashboard' })`（本 profile 已装 better-sidebar，展开侧边栏并聚焦页签）；未装时回退 `ctx.get('layout').openRightbar(true, false)`（显示宿主右侧栏）。
- 服务用 `ctx.get` 动态读取，不写进 `exports.inject`，避免宿主缺服务时整个插件 pending。

### 实现修订（2026-11-08，浏览器实测通过）

- 正确落点：`conversation.session.header.actions`（list 槽；`corner` 是 single 被宿主占用，注册不进去）。
- 关键修复：list 槽注册选项用 **`id`**（不是 `key`，否则报 `list slot ... requires options.id`）。
- 组件在模块级定义，`ctx` 通过注册包装器 `(props) => h(OpenWorkflowButton, { ctx, sessionId })` 传入（模块级函数直接引用 apply 的 ctx 会 ReferenceError）。
- 点击逻辑：`ctx.get('betterSidebar').openTab({ type: 'awf-dashboard' })` 展开侧栏并聚焦页签；未装 better-sidebar 时回退 `ctx.get('layout').openRightbar(true,false)`。
- 浏览器实测：按钮渲染 ✓；点击后 betterSidebar 获取成功、openTab 执行、Agent Workflow 面板出现且内容渲染 ✓。
- 单元测试 56/56；已同步 profile 安装副本。

### 最终形态（2026-11-08，浏览器实测通过）

- 位置：`conversation.session.header.utilities`（list 槽），DOM 挂载后左移两位（插到第 4 位，与相邻按钮互换位置）。
- 图标：改用 DSH 原生图标集 `dsw-icon-checklist-outline-regular`（`<use>`，14px 匹配原生 15px），不再用手绘 svg。
- 尺寸/样式：按钮 24、图标 14（≈原生 28/15）；hover 背景 0.18（激活 hover 0.30），激活底色 0.22。
- 高亮逻辑（hooks）：`useState` + `betterSidebar.subscribeState` 订阅；仅当**底部面板打开且工作流看板可见**时高亮，否则默认透明；不依赖 hover/点击。
- 点击逻辑：高亮态（看板显示中）→ 点击头部「折叠底部面板」关闭；否则 `openTab` 打开并通过「展开底部面板」确保展开。
- 浏览器实测：打开→高亮+面板展开 ✓；高亮态再次点击→面板收起+高亮复位 ✓；单元测试 56/56；已同步 profile。

### 终版（2026-11-08，右侧栏方案 + 状态同步）

- 判定改用 **DSH 原生右侧栏**（不再用 better-sidebar openTab，避免打开底边栏）：看板在 `sidebar.right.pane.tab` 页签里。
- 点击：`ctx.layout.closeRightbar()` 收起（看板显示中）／ `ctx.layout.openRightbar(true,false)` 打开并点击 Agent Workflow 页签激活（未显示时）。
- 状态同步：`useState` + MutationObserver（aria-selected/class/style）+ 500ms 轮询兜底；高亮仅当右侧栏可见且 Agent Workflow 页签 `aria-selected=true`；切到其他页签或收起时恢复默认。
- 浏览器实测：关闭→点击打开+高亮 ✓；高亮态再点→收起+高亮复位 ✓；切到「文件」→ 高亮自动消失，切回→恢复 ✓；56/56 测试通过。

### 最终交互设计（2026-11-08，用户确认）

- **打开**：用 `useRef` 记录打开前的侧栏状态（是否打开 + 当前激活页签）；若未开 → `layout.openRightbar(true,false)`；随后激活 Agent Workflow 页签。
- **关闭**：先切回打开前的页签（关闭工作流显示）；若打开前侧栏是关的 → `layout.closeRightbar()` 恢复收起；原来开着则保持打开。
- 宿主「打开/收起右侧边栏」按钮的 DOM 点击不可靠，统一用 `layout` API；页签切换用点击（实测有效）。
- 实测：关→开（侧栏+页签+高亮）✓；开→关（恢复原状态+高亮复位）✓；切页签高亮同步 ✓。

### 打开/关闭流程最终版（2026-11-08）

- 打开：记录侧栏状态 → `layout.openRightbar` → `ensureWorkflow` 重试：有 Agent Workflow 页签则点击激活；右侧栏空面板（无页签）则点「新标签页」→ 在弹出菜单点 Agent Workflow 添加页签 → 直到看板内容可见。
- 判断「显示中」用右侧栏内容特征（当前任务/工作流已最新/最近完成/待办），不依赖页签 aria-selected（页签可能是普通 DIV）。
- 关闭：先 `layout.closeRightbar` 收起（关闭工作流）→ 若打开前侧栏是开着的，重开并切回原页签；否则保持收起。
- 亮度：激活态背景 0.28（> 普通 hover 0.18），激活 hover 0.34。
- 实测：关闭后点击 → 自动打开+激活+高亮 ✓；高亮态再点 → 收起/恢复 ✓；窗口重启后重开可用 ✓；56/56。

### 打开/关闭最终交互（2026-11-08，浏览器实测）

- 打开（侧栏关闭时）：点「打开右侧边栏」按钮（真实 pointer/mouse 点击序列，`element.click()` 无效）→ 宿主弹出「新标签页」菜单 → 点菜单里的 Agent Workflow（真实点击）→ 看板显示。
- 打开（侧栏已开但无工作流页签）：同样走「新标签页 → Agent Workflow」；已有页签则直接点击激活。
- 关闭：点击右侧栏页签自带的「关闭」按钮（关闭最后一个页签时宿主自动收起侧栏；开着其他页签则保持——即自动恢复打开前状态）。
- 状态同步：`useState` + MutationObserver + 轮询；判断看板显示用右侧栏内容特征。
- 实测：关→开+高亮 ✓；开→关+透明 ✓；56/56。

### 打开/关闭（最终）：按右侧栏开合切换

- 判断切换用「右侧栏是否打开」（不依赖看板内容特征，避免判定失效导致关不掉）。
- 打开：未开 → 点「打开右侧边栏」；已有工作流页签则激活，无页签则「新标签页 → Agent Workflow」添加。
- 关闭：`layout.closeRightbar()` 收起侧栏（**保留页签**），下次打开直接显示看板、不再弹新标签页菜单。
- 高亮：侧栏打开且看板内容可见；激活底色对齐原生选中页签（白 0.08）。
- 实测：关→开（显示+高亮）✓；开→关（收起+透明）✓；56/56。

### 最终可用方案（2026-11-08，用户确认）

- 关键：注册右侧栏 **tab 类型（stage 1）** `sidebarRightTabs.register({ id: 'awf-dashboard', kind: 'awf-dashboard', title: () => 'Agent Workflow', priority: 'extension' })`，body 仍由 `sidebar.right.pane.tab`（key=id）提供。
- 打开：`ctx.get('sidebarRight').openTab('awf-dashboard')` → **直接打开工作流页签**，不经过默认页签/空面板/「新标签页」菜单（用户确认效果很好）。
- 关闭：点页签自带「关闭」按钮（或 `layout.closeRightbar` 兜底）。
- 高亮：`useState` + MutationObserver/轮询，侧栏开且看板内容可见才高亮；激活底色对齐原生选中页签（白 0.08）。
- 实测：关→开（直达、无菜单、高亮）✓；开→关（收起、透明）✓；56/56。
