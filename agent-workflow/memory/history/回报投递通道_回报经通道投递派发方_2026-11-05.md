# 回报投递通道：目标回报经通道投递派发方，派发方无需轮询（DISPATCH-146，DEV-156）

日期：2026-11-05。目标：实现「回报通道」——必报点规则（DISPATCH-145 说什么）不变，本任务实现怎么送达：目标会话回报时 awf-dispatch 自动投递到派发方会话，派发方无需轮询。

## 选型（实证结论，勿再重做）

- **主通道 = harness RPC**：`session/prompt`（mode=queue）把【回报投递】消息推进派发方会话收件箱（inbox）——实证（一次性空会话）：消息作为 user/message 入 inbox 且**自动触发一次回合**（idle 时），派发方无需轮询。=> `--report` 投递实现为 `DshApi().prompt(to, msg)`。
- **降级通道 = 收件箱文件**：RPC 不可达（GUI 关/无凭证/未注入派发方会话）或未指定 `--to` → 追加写 `<cwd>/dispatch/reports/inbox/<来源会话ID>[-<派发单>].md`（派发方查 git/账本时可见）。
- **派发方会话捕获**：派发方运行 awf-dispatch 时其进程 env `DSH_SESSION_ID` = 派发方会话 → 注入 build_prompt「回报投递通道」小节（含 `--report --to <id>` 命令示例）+ log_entry 记 `- 回报通道：派发方会话 <id>`。
- 消息格式：`【回报投递】` + 时间戳（`%Y-%m-%d %H:%M:%S %z`）+ 来源会话 + 派发方会话 + 派发单 + 回报正文——派发方收件箱可完整归因。
- **不另建 registry**（简化）：会话 ID 已由注入文本告知目标 + log.md 审计；后续要全文检索时再加。

## 接口（命令兼容性约束）

- `--report` 是**新增独立模式**：第一个位置参数 = 回报文本（与宣传形式 `awf-dispatch --report --to <id> "<回报文本>"` 一致），也可 `--text` 或 stdin；第二个位置参数（task）与 `--prune/--session/--headless/--handoff/--wait` 互斥（parser.error，退出码 2）。
- `--to/--from/--ticket/--dry-run`（dry-run 只渲染不联网，smoke 可用）；成功=0，缺文本/组合非法=2。既有调用方式与退出码不变。

## 关键坑（本任务实证，防再踩）

1. **python3.9 tokenizer 长行 bug**：源文件行 >1024 字节且含多字节字符时，直接执行（非 py_compile）会报「Non-UTF-8 code starting with '\xe8' … but no encoding declared」——字节本身合法 UTF-8，是 tokenizer 分块解码在行内切断了多字节序列；行偏移一变就触发（本任务插入代码后触发，HEAD 版侥幸未触发）。**修复：文件头加 `# -*- coding: utf-8 -*-`**（tokenizer 改按行整体解码）。教训：awf-dispatch 这类超长中文行文件必须带 coding 声明。
2. **argparse 位置参数语义**：`--report "<文本>"` 的文本会占用 target 位置槽——互斥校验必须只拦第二个位置参数（task），否则宣传的命令形式被自己拦死（第一次实现就因此全模式报错，修正后自测通过）。
3. **`--dry-run` 必须零副作用**（不建 DshApi、不写文件）——smoke 才能无 GUI 断言；互斥错误 grep '不能与'。
4. 既有短语（必报点总表/时机/字段/违约/转派链/静默等待=违规等）**逐字保留**，新增全部追加式——smoke §30.11/30.12 精确 grep 是兼容性约束。
5. 双副本：bin/awf-dispatch ↔ agent-workflow/bin/awf-dispatch、templates/AGENTS.md.tmpl ↔ agent-workflow/templates/AGENTS.md.tmpl、templates/workflows/*.md ↔ agent-workflow/workflows/*.md——改源后 cp 同步，check_workflow（copy_drift_report）断言 diff 空；改 tmpl 后必须 `./agent-workflow/bin/awf bootstrap` 刷新 AGENTS.md（digest 变）。
