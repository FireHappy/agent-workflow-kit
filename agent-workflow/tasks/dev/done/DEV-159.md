## [DEV-159] 派发会话数量上限硬约束：--new 也受同派发者同项目 ≤3 约束

| 字段 | 内容 |
|------|------|
| 优先级 | P1 |
| 状态 | done |
| Owner | lead |
| 协作模式 | single |
| 来源任务 | 用户截图指出：同一派发者（im）在 agent-workflow-kit 工作区堆了 6 个 [awf] 会话（上限 3 被突破） |
| 修改范围 | bin/awf-dispatch、agent-workflow/bin/awf-dispatch（同步副本）、test/smoke.sh |
| 最近更新 | 2026-11-05 |

### 根因
`--new`（argparse dest="reuse" store_false）无条件新建、跳过 select_reuse_session 的复用/并发池检查——多次 --new 派发同派发者同项目任务时会话无限堆积（实测 kit 工作区 sender=im 堆到 6 个；空档期 DISPATCH 系列多次 --new 造成）。

### 修复
新建路径（session_id is None）加数量上限检查（DEV-159）：同 cwd + 同派发者键（row_sender_key）的 [awf] 会话数 ≥ MAX_SENDER_SESSIONS(3) 时拒绝新建，提示复用/清理（--prune）后重试；显式 `--force` 为逃生口（旧会话坏掉/阻塞需强制新建）。非 --new 路径原本就有并发池约束（≤3），本次补的是 --new 的数量约束。

### 验证
- 三场景单测：sender=im 已有 3 个 → 拒绝（错误含「已有 3 个」「上限 3」）；其他 sender → 正常新建；--force → 强制新建 ✓
- smoke：新增 pool3 用例（run_dispatch new=True 强制 reuse=False），全量 213/0 ✓
