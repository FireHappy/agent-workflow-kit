# 派发会话命名规则（DEV-134）沉淀

日期：2026-11-04 ｜ 结论来源：用户三轮设计确认 + smoke/单测回归

## 最终规则：`[awf] [派发者] [任务名]`

- 派发者：`--sender <名>` > 票据「派发者：<名>」行 > 默认 `lead`
- 任务名：当次票据的 `ID 短标题`（task_display，如 `UP-102 版本锚点`），随派发动态更新
- 标题不写目标项目名（会话本来就在目标项目工作区里，用户明确否掉了 `[awf] 周报` 里的项目名）
- 任务完成**不做还原**（用户明确；标题保留最近任务名 = 可辨识历史）

## 会话收敛（用户模型：先空闲复用，忙则看池）

同派发者同项目最多 3 个 [awf] 会话（MAX_SENDER_SESSIONS=3）：
1. 池内空闲（running=False）→ 复用，改名接新任务（reuse_rename_needed + api.rename）
2. 都忙且池未满（<3）→ 新建扩充并发
3. 池满（=3）都忙 → 返回忙碌候选，调用方 wait_for_idle（--queue-timeout，默认 60s 超时）

## 实现要点（踩坑）

- 复用键段级精确匹配：`awf_title_sender(title)` 提取 `[awf] [<派发者>]` 段，避免 `[lead]` 误吞 `[leadership]`
- 旧格式 `[awf] <项目>`（DEV-126 时代）按 lead 池处理（row_sender_key 兜底 "lead"）——平滑升级复用改名，不新建堆积
- 用户普通会话 `<项目> · xxx`（无 [awf] 段）不算池，走 legacy_probe（RT-1 防误吞）
- Python 坑：`clean_title("")` 返回 `未命名任务`（非空）→ 空 sender/task 的 `or "lead"` 兜底失效，须先判断 `(x or "").strip()` 再调 clean_title
- 坑：`bin/awf-dispatch` 带连字符不能直接 `import`（测试用 SourceFileLoader 或 compile exec 加载）
- 坑：模块 docstring 内不能用 `""".format()`（会把三引号提前闭合炸语法）

## 其它

- `--title` 完全定制标题仍优先（覆盖默认格式）
- dispatch/log.md 记录「模块 / 会话来源 / sessionTitle」；--json 输出含 sessionTitle
- 复盘：用户第一版想要 `[awf] [派发者] [任务名]`（怕会话多），讨论后确定「池上限 3 + 空闲复用 + 满则等待」折中——既有并发又收敛
