# unity 打包跨项目必须派发（教训）

> 2026-11-07 实测。关联：unity-build-install 技能「任务路由」节。

## 背景
主会话（agent-workflow-kit）直接操作 uxrsample 的 Unity 编辑器打包，多次卡死：
- RokidImageLibraryBuildProcessor 的 DisplayProgressBar 在屏幕休眠时挂起 → MCP `build/start` 30s 主线程超时
- 反复重开编辑器/轮询产物，长期占用主线，且目标仓库是跨项目（uxrsample ≠ 当前工作区）

## 结论（沉淀为技能硬规则）
- **打包目标 ≠ 当前工作区 → 一律 `awf-dispatch` 派发**到目标工作区会话执行，调度方不直接操作目标 Unity
- 派发票据必须携带硬约束：不配置场景 / 无工具默认打包 / 场景零改动校验 / 产物路径
- 目标 agent 在其工作区加载 unity-build-install 技能执行
- 修正：unity-build-install SKILL.md 新增「任务路由」节（在触发规则后、打包决策前）
