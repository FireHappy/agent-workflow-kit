# 派发生命周期闭环（DISPATCH-133）沉淀

日期：2026-11-04 ｜ 结论来源：用户决策（"防止遗忘"锚点）→ 五步闭环

## 核心动机：防止「派发了就忘记」

异步派发后主会话立即脱手，若派发方账本无记录，派发方会忘记任务存在——尤其代理失败、无回报、静默中断时。**派发方账本的 active 任务 = 记忆锚点**：无论成功/失败/中断，账本始终可见「有一条派发在进行中、目标是谁、何时收尾」；**归档 done 是派发方核验收讫后才做的动作，不是代理单方面的**。

## 五步闭环（写入 docs/dispatch.md 标准派发流程）

1. 分析意图 → 路由裁决（落盘票据头部：来源/目标/通道/理由）
2. **派发方账本登记 active**（字段：目标 worker / 关联票据 / 派发时间 / 一句话目标 / 验收标准）
3. 异步派发（子代理，默认不 --wait；DEV-138）
4. 代理完成任务包五项回报；异常（失败/超时/无回报/核验不过）返回派发方决策
5. **派发方核验后归档 done**（补完成日期/结果概要/commit 引用），dispatch/log.md 留流水

**失败/无回报分支**：保持 active / 置 blocked **不归档**；例行扫描账本发现滞留 → 追问 / 重派 / 上报用户决策。

## 要点

- 票据生命周期（dispatch/tasks/*.md → --prune 归档）≠ 派发任务生命周期（派发方账本 active → done）：票据记录「派发了什么」，账本记录「是否收讫」，**两者都要闭合**。
- 与 DEV-138 三规则（异步/子代理/瘦身）在同一文档衔接；本任务自身就是一次闭环演示（dsh-im 派发 DISPATCH-133 → kit 认领 DEV-139 → 归档）。
- 不做自动化强行绑定：登记/归档由派发方按流程手动完成；不改 awf-dispatch 行为代码。
