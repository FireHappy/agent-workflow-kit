# 派发会话标题统一由框架生成：--title 收窄为任务名（DEV-228）

日期：2026-11-08 ｜ 关联：DEBUG-001 归因收尾（dsh-settings 派发传裸 --title → 无法 --retire-session）
同主题先例：`派发会话命名_2026-11-04.md`（DEV-134）、`派发会话物理删除排查_归档退役_2026-11-08.md`

## 决策：方案 A+B（用户认可，拒绝 C）

- **A（主）**：`--title` 不再作完整标题字面值，只作**任务名**喂给 `awf_session_title(sender, title)`
  ——标题恒为 `[awf] [派发者] [<title>]`，前缀由框架保证，`--retire-session` 前缀判据稳定可过。
- **B（兼容）**：`--title` 已显式带 `[awf]` 前缀（旧用法/高级场景）→ 原样使用，不二次包装。
- C（裸标题直接报错拒派）只作后备讨论：拒派体验差，A 已覆盖，不实施。

## 实现落点（awf-dispatch）

```python
def resolve_session_title(title_arg: str, sender: str, fallback: str) -> str:
    title_arg = (title_arg or "").strip()
    if title_arg.startswith(AWF_TITLE_PREFIX):
        return title_arg                       # B：显式 [awf] 原样
    return awf_session_title(sender, title_arg or fallback)   # A：恒带前缀
```

- 唯一生效点 = `dispatch_session` 的 `session_name = resolve_session_title(args.title, sender, task_display(task, text))`
  —— rename/create/复用改名（2561/2583/2710/2738 附近）全走该变量，一处生成全局生效。
- main 里的展示/交接单/headless `title`（`args.title or f"{target.name} · ..."`）同步归一
  （仅 --title 分支走 resolve；无 --title 保持 `target · task` 展示不变）。
- 顺带修复边角：旧 `args.title or awf_session_title(...)` 对空白串 `"  "`（truthy）会把空白当标题，
  新逻辑 `(title_arg or "").strip()` 兜底默认任务名。

## 并发踩坑（DEV-215 实例）：并行会话 `git add -A` 吞入工作树改动

- 现象：edit 写入后 `git status` 为空、`git hash-object` == HEAD hash —— 一度以为文件系统视图分裂。
- 真因：并行会话 `git add -A && git commit` 把我**未提交的工作树改动连同它的提交**一次吞入
  （`git show <commit> -- <file>` 逐字核验：内容=我的最终版，零夹带）。
- 定位方法：`git reflog`（看 HEAD 何时被移动）+ `git show HEAD:$file | grep 特征`（HEAD blob 是否已含我的改动）
  + `git show <commit> -- <file>`（确认吞入内容一致性）。
- 处理：不 panic、不改写历史；在任务块记「并发记录」，自己的 commit 补做（消息仍含任务 ID）。
- 提示：共享工作树 + 并行会话环境下手头的未提交改动随时可能被吞，关键改动尽快 commit。
