# 派发兜底锚点应登记在派发方账本（教训）

日期：2026-11-07 ｜ 关联：DEV-028（dsh-settings 撞号收尾）

## 现象
派发 uxrsample 打包任务时，把「兜底锚点」错误登记到了 **dsh-settings 项目的账本**（tasks/dev/current/DEV-026.md），与该项目自己的 DEV-026（路径同步任务）撞号。撞号导致 done/ 与 current/ 出现两个 DEV-026，需派发收尾改号。

## 根因
派发方的兜底锚点（active 兜底、记录「已派发、待核验」）应登记在**派发方自己的账本**（agent-workflow-kit 的 tasks/），而不是目标项目账本。目标项目账本由目标 agent 自己维护（其任务的 ID 空间）。

## 规则
- 派发方账本：登记派发任务本身（DEV-xxx，含路由裁决/验收）
- 目标项目账本：只由目标 agent 写自己的任务（认领/归档），派发方不直接写入——避免 ID 空间冲突
- 若确需在目标侧留状态标记，用目标自己会话的 current.md 由目标 agent 维护，不预写

## 验证
- dsh-settings current/DEV-026 → done/DEV-028 改号收尾完成（eca2a72），done/ ID 恢复唯一
